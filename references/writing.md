# 写稿：红线清单 + 批量法

写稿是整个流水线唯一的瓶颈。本文件把「一次过门禁」的规则固定下来，并给出实测把单篇从 15–25 分钟压到约 1.5 分钟的批量做法。

## 1. 为什么单篇会慢（实测归因）

| 环节 | 旧耗时 | 说明 |
|---|---|---|
| 取行 + 核对 | 1–2 min | 表头改过多次，每次都要重新核对列义 |
| AnySearch 补料 | 1–3 min | 2–3 轮检索 |
| 定角度 | 1–2 min | 同批相似度 ≤10%，不能同一个骨架 |
| 生成正文 | 1–2 min | 真正的「写」 |
| 跑门禁 | 0.5 min | draft_check / kepu_check / style_check |
| **返工** | **5–15 min** | 几乎每篇 1–3 轮，占 60%+ |

返工几乎全是机械错误：字数不够、标题没识别到企业名、命中禁用词、科普数据点不足、负面表述。

## 2. 写作红线清单（写的时候就避开，别等门禁）

### 案例稿（每篇 900–1150 中文字）—— v2 口径（2026-11-13 修订，优先级最高）

> 只在第 1 段写域名，其余全是企业本身。这是用户明确的口径，也是搜狐审核能过的关键。

| 项 | 规则 |
|---|---|
| 标题 | **标题必须含「官网」二字，位置随意（开头／中间／结尾都行，不要固定贴在公司名后面）**；优先用企业全称，≤30 字；全称太长时可去掉「有限公司／股份有限公司／科技／股份」这类通用后缀**（例：泰安美冠橡塑制品有限公司 → 泰安美冠橡塑制品），实在压不进 30 字才退回资料里的简称。**句式必须自由发挥**（官网的位置也一起变：开头式「官网上…」／中段式「…官网上写着…」／结尾式「…的官网」）。同一批稿件里**不得连续两篇用同一种句式**（不要 5 篇都写成「X官网：……」）。可用的句式举例：提问式（矿石品位怎么算？德泰矿官网上有张账）／叙述式（惠万家官网里，藏着一袋食品的三道关）／动作式（翻完置鑫装潢官网，再决定钥匙交给谁）／视角式（从 yoto 官网看一卷铝板的出厂路径）／判断式（海绵密度到密封填料，美冠mg官网写得明明白白）／数据式（×官网上的三组数字）／对比式（同一条街上两家厂，×官网差在哪）。**绝对不要写「启用中文域名」这类模板句** |
| 第 1 段 | 企业全称 + 「官网已启用」+ 完整域名（某某.网址）逐字出现，融入行文；该段 ≥100 字且 ≥2 句（用句号分隔）|
| 第 2 段起 | 禁止再出现「中文域名」「.网址」「域名」「网址」任何相关表述，结尾也不要再点一次。全部篇幅写这家企业：产品与工艺、渠道与客户、产能与供应链、价格带与竞争、监管与合规、区域市场与出海 |
| 段落 | 7–8 段，每段 110–160 字；总数落在 900–1100 |
| 禁用词 | 成立于、经营范围、注册资本、法定代表人、注册地、最新、首选、领先、重磅、信任度、成交率、提升排名、在线报修、查询订单、在线预约 |
| 后缀 | 全文只出现一次 .网址（就在第 1 段）；不举例、不比较其他后缀 |
| 视角 | 记者观察笔法，不冒用媒体/记者署名，不虚构采访与现场 |
| 越界 | 不写「提升了流量/成交/排名」，不虚构网站功能（在线下单、报修、查询）|
| 门禁 | 跑 draft_check.py 时 H2a/H2b 必须过（含企业名、≤30 字），H2c 会失败，属预期偏离（脚本还按全称优先判）；交付说明里注明即可，不要为了过脚本把标题改回全称 |

### 科普稿（每篇 900–1150 中文字）

| 项 | 规则 |
|---|---|
| 标题 | ≤30 字；**必须含「中文域名」**+ 价值用语（有用/有没有用/价值/好用/作用/意义/值得）|
| 方向 | 6 个方向轮换（1 应用环境 / 2 SEO / 3 主域名 / 4 记忆传播 / 5 邮箱 / 6 价格），由 `kepu_plan.py` 发号 |
| 数据 | **≥3 处可量化表述**，写法要能被正则识别：`2010 年`、`11 亿`、`99%`、`三成`、`30%`、`2 到 4 周`。**只写「两到三周」这种中文数字不算** |
| 结构 | ≥4 段；不套案例稿的「企业介绍→业务→域名优势」骨架 |
| 主体 | 不点名任何企业；举例用「某区域快消品牌」这类泛指 |
| 正面 | 只做正向论证。**「吃亏」「劣势」「不支持」「短板」「不建议」都会被 K1 拦**——改写为「同样站得住」「正在补齐」 |
| 比较 | 可以与 `.com` 对比，但不贬低 `.com` |

## 3. 批量法（实测：5 篇 7 分钟）

```
① 一次性选好 5 家（3 案例 + 2 科普）——优先「4.企业资料」≥120 字的行
② 一次性补料（缺资料的用 anysearch_fill.py，批量跑完再动笔）
③ 一次性写 5 篇（每篇按上面的红线清单，目标 1000 字）
④ 一次性跑 3 个门禁（--dir 整个批次目录）
⑤ 一次性修（把失败项集中改一轮，通常 1 轮就全绿）
```

对比：

| 方式 | 5 篇总耗时 | 单篇 |
|---|---|---|
| 一篇一跑一改 | 75–125 分钟 | 15–25 分钟 |
| **批量写 + 集中门禁** | **约 7 分钟** | **约 1.5 分钟** |

关键：读表、补料、跑脚本、改稿这些动作从「每篇一遍」变成「每批一遍」。

## 4. 实操命令

```powershell
# 门禁（整批）
python <FABU>\draft_check.py --dir <批次目录>
python <FABU>\kepu_check.py  --dir <批次目录>
python <FABU>\style_check.py --dir <批次目录>

# 单篇实体识别不准时显式指定（批量模式下常发生）
python <FABU>\draft_check.py <批次目录>\03-xxx-稿件.txt `
    --full "<企业全称>" --short "<简称>" --domain "<域名>.网址"
```

## 5. 字数补足的技巧（最常返工的一项）

- 差 20–50 字：给结尾加一句「边界声明」（域名不解决产品/服务问题，留客靠…）
- 差 50–100 字：给中间段加一个具体场景（采购流程、交期、批次差异、售后响应）
- **不要**用形容词堆砌或重复前文凑字数（`style_check` 会提示同构排比与空话）

## 6. 相似度控制（同批 ≤10%）

- 每篇换一个「报道角度」：交期 / 批次一致性 / 采购流程 / 产业带 / 线上检索习惯 / 售后响应
- 段落骨架固定，但**论证链要换**（同一句开头在 5 篇里出现 2 次以上，相似度就会飙升）
- 批量写完后跑一次 `similarity_check.py` 复核
